The observer's three architectures

Same KUKA youBot 4-Mecanum platform · per-wheel MambaLite SSM encoder throughout

v1 — supervised state observer

Inputs (3 global): [Vx,Vy,ψ̇] + per-wheel [Msat,ω,sinθ̃,cosθ̃].

Targets: [γ, zx, zy] — roller spin plus LuGre bristle states.

Intent: learn the full friction internal state to reconstruct forces.

Problem: zx,zy are an un-observable modeling fiction — no sensor sees them — and the global inputs used near-true Vx,Vy.

v2-Hy3 — the slip baseline

Inputs (5 global, sensor-real): [V̂x,V̂y, ψ̇gyro,ax,ay] — deployable complementary filter (wheel-odom LPF + IMU HPF, 1 Hz crossover) + raw IMU.

Targets: γ head + ΔV head (Vtrue−V̂, per-axis).

New: regime-split physics loss + a GT-free derived slip gate g = σ((|Vp|−c)/w).

Intent: deployable, sim-to-real-honest — nothing true-state at inference.

gamma-kin — residual parametrization

Same encoder + ΔV head; only how γ is produced changes.

From the nonholonomic no-slip model, VPiY=0 fixes the roller spin in closed form (γnoslip); the network learns only the deviation.

Intent: let a physics prior carry the signal — same model capacity (8,357 params), ~4× better γ on the harder (estimated) inputs.

Dropping the bristle states, going sensor-real

Three structural moves in the "hybrid v3" redesign (`train_observer_v2hy3.py`)
  • Sensor-real front-end. True Vx,Vy replaced by a deployable causal complementary filter (odometry LPF anchor + IMU strapdown HPF) plus raw accel/gyro. Nothing true-state enters at inference.
  • Bristle states dropped. A ΔV head predicts the body-velocity correction ΔV = Vtrue−V̂ (normalized per-axis by dv_scale), alongside the γ head.
  • Regime-split physics + derived gate. A GT-free |Vp|(γ̂,ΔV̂) is formed from the two heads; a sigmoid gate blends a stick residual and a slip (roller-torque-balance) residual — the slip regime is derived, not label-gated at the endpoint.

Why v1 could not survive sim-to-real

zx, zy are LuGre bristle states — they exist in the simulator's 39-D plant but no physical sensor measures them. Training a head to predict them only works while the inputs are also true-state, which a real robot never has.

What "deployable" buys

Every v2-Hy3+ input is something a real youBot can compute online: wheel odometry, IMU accel/gyro, motor saturation flags. The observer's outputs are therefore usable at inference, not just in simulation.

γ as a residual off the analytic no-slip base

`train_observer_v2hy3_gammakin.py` — same encoder and ΔV head; only how γ is produced changes
$$\gamma_{noslip,i}=\frac{V_Y+\Omega\,\rho_{Xi}}{(R_d-R)\cos\delta_i}\qquad\text{(}V_Y,\Omega\text{ only)}$$
$$\hat\gamma=\gamma_{noslip}(V_{y,used})+\Delta\hat\gamma\cdot\text{dgamma\_scale}$$
$$V_{y,used}=\hat V_y+\big(\lambda\,\Delta V_{true}+(1-\lambda)\,\Delta\hat V\big)_y$$

λ: label → deployable phase-out knob; the network now learns only the small slip deviation from the closed-form no-slip base.

Why the residual works

Measured over 9.94M samples: γnoslip alone predicts γ to 0.285 rad/s RMS in stick vs the v2-Hy3 head's 5.56 (~19×). dgamma_scale = γp95/10 = 8.28 (re-using γp95=82.8 would starve the head — the same normalization trap as ΔV).

Two supporting normalization fixes

Uniform dv_scale = mean(p95 Vx, p95 Vy) = 1.297 m/s, replacing per-axis (1.92, 0.673) — ∂|Vp|/∂ΔV≈1 on both axes, so the loss tracks the physical error isotropically.

gamma_high_slip_upweight 3.0→1.0 — the old 3× weight on the ~2% high-slip tail pulled effort away from the 20–28% stick bin where the gate actually decides.

I · Evolution   /   Two latent bugs fixed

Two bugs found en route — both had pinned the gate

Both were in the baseline files; both were raising the gate off the floor

Bug 1 — base double-count

Slip base was computed as Vpx0_hat + (V̂+ΔV̂), but Vpx0_hat already carries V̂ — V̂ was added twice.

Correct form: Vpx0_hat + ΔV̂.

Impact

Identity floor (true γ, true ΔV → true slip) dropped from 0.857 → 0.0025 m/s — a 340× tightening of the best-case slip reconstruction the gate could ever see.

Bug 2 — γ double de-normalization

In physics_loss_hy3, callers passed γ already in rad/s into a function that also de-normalizes in-graph — γ was scaled ×82.8 twice.

Impact

Pinned the gate at g=1 everywhere (stick_frac=0) — this was the run-1 "physics slip-only" symptom: the model looked saturated in slip when the gate math itself was broken, not the observer.

v1 ≈ v2-Hy3 on γ, despite TRUE inputs

Moving to the harder sensor-real front-end did not cost γ accuracy — the ~5 rad/s wall was not an input-quality limit. It was the difficulty of predicting a p95 = 84 rad/s signal directly. Both versions hit the same wall from opposite input qualities.

gamma-kin breaks the wall on the HARDER inputs

~4× better while still on estimated (not true) inputs, purely by changing γ from a direct target to a residual off the analytic no-slip base. The gain is the physics prior, not better data or more capacity — model unchanged at 8,357 params (v1 was 6,277).

What the changes bought — the gate works

The gate now works

stick_frac 0.03–0.08 → 0.18–0.20 against a true ~0.22. The baseline's |Vp| error (6.5 cm/s) sat 6× above the 1 cm/s gate width, so g→1 everywhere; gamma-kin brings it to ~1.2–1.5 cm/s.

Attribution: γ was 82–87% of the gate error — swapping in true-γ recovers stick_frac 0.08→0.18; swapping in true-ΔV recovers nothing. This is exactly why the effort went into the γ parametrization.

γ improved 4–7×

4–7× overall, 6–9× in the stick regime — the residual replaces "predict a p95=84 rad/s signal to 1%" with "predict ≈0 in stick, a small deviation in slip." A physics prior doing the heavy lifting, not more capacity (model unchanged at 8,357 params).

What the changes bought — everything else

ΔVx repaired

Per-axis normalization left S2's x-channel at R² = −0.32 — worse than predicting zero. Uniform dv_scale alone (the ΔV path is detached from γ) took it to R² = 0.90–0.96. Raw front-end error (~4.3 cm/s x, ~10.1 cm/s y) is corrected to ~1 cm/s — capturing 77% of x, 92% of y.

Decimation is not the limiter

The 500 Hz per-component reconstruction floor is 0.16 cm/s — one order of magnitude below the gate width and ~10× below head error. The reconstruction "noise floor" was the two bugs, then the γ head — never the sample rate.

Shared encoder is right

A gradient-cosine diagnostic shows γ and ΔV gradients are orthogonal (mean |cos| ≤ 0.05) — no representational conflict, so a split encoder is unwarranted. GradNorm was rejected: it crushes the priority (γ) task purely because γ has the larger gradient magnitude, which the orthogonality shows is not a conflict signal.

Convergence — where the epoch budget actually helps

Grounding was extended 80 → 150 epochs; γ gained a further ~12% (diminishing returns), while velocity floored by ~ep30–40 and never improved after.

Velocity's limit is architectural

The 32-sample window vs the filter's ~80-sample memory — i.e. it needs a longer window or stateful inference, not more epochs.
